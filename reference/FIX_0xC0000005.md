# Fix for 0xC0000005 Access Violation Error

## Problem
The code was experiencing 0xC0000005 (Access Violation) errors, which typically occur due to:
- Memory corruption in audio processing (librosa's STFT operations)
- Cross-thread memory access issues
- Unmanaged heap memory with concurrent operations

## Root Causes Identified
1. **Unsafe librosa operations**: Direct calls to `librosa.effects.time_stretch()` and `librosa.effects.pitch_shift()` without proper error handling
2. **Thread safety issues**: Audio data passed between threads without proper copying
3. **Memory leaks**: No cleanup of large audio buffers after processing
4. **Concurrent access**: Multiple threads accessing the same audio arrays

## Solutions Implemented

### 1. Safe Time Stretching (`safe_time_stretch()`)
```python
- Creates a copy of audio data before processing
- Clamps stretch rate to safe values (0.5-2.0)
- Returns original audio if operation fails
- Proper error handling and memory cleanup
```

### 2. Safe Pitch Shifting (`safe_pitch_shift()`)
```python
- Creates a copy of audio data before processing
- Clamps pitch shift to safe range (-12 to +12 semitones)
- Returns original audio if operation fails
- Proper error handling and memory cleanup
```

### 3. Thread-Safe Playback (`playback_thread()`)
```python
- Uses semaphore to limit concurrent playback threads
- Makes a copy of audio data to prevent cross-thread corruption
- Validates sample rate ranges (8000-192000 Hz)
- Proper cleanup with garbage collection in finally block
```

### 4. Memory Management
```python
- Added explicit `del` statements to release audio arrays
- Added `gc.collect()` calls after large memory operations
- Imports added: `import gc`
```

### 5. Parameter Constraints
- **Pitch shift**: -8 to +8 semitones (was -12 to +12)
- **Time stretch**: 0.7 to 1.5x (was 0.5 to 1.8x)
- **Playback rate**: 0.6 to 1.4x (was 0.5 to 1.5x)
- **File size**: Max 2MB (was 1MB)
- **Min file size**: 512 bytes (was 1024 bytes)

### 6. Added Retry Logic
- `prepare_random_sample()` now attempts up to 10 different samples
- Skips problematic files and tries alternatives
- Graceful fallback if all samples fail

## Key Changes Summary
| Aspect | Before | After |
|--------|--------|-------|
| Audio copying | Direct reference | Deep copy per thread |
| Error handling | Basic try-catch | Safe wrapper functions |
| Memory cleanup | None | gc.collect() calls |
| Concurrent threads | Unlimited | Limited by semaphore |
| Sample rate range | Any | 8000-192000 Hz validated |
| Retry logic | Single attempt | 10 attempts with fallback |

## Testing Recommendations

## Additional Notes
- The semaphore ensures only one playback thread is active at a time
- All audio data is copied before processing to prevent corruption
- Garbage collection is explicitly called after large allocations
- Parameter ranges are conservative to prioritize stability
